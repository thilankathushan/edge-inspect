## Fixed data and preprocessing decisions

- Official `train/good` only: sort by SHA-256 of `seed + newline + category-relative path`, with path tie-break. Reserve `ceil(0.20*N)` images for **normal_calibration** and the remainder for **model_fit**; require at least one of each. Default seed 42. Freeze manifest bytes/hash before fitting. Changing files, seed, or protocol creates a new experiment.
- All official test normals/anomalies are **final_test**. Their masks stay paired with test anomalies. They never enter fitting, calibration, threshold selection, preprocessing statistics, or model selection. The default data iterator rejects the final-test role unless explicitly enabled for final evaluation.
- Accept PNG/JPEG/BMP/TIFF, dimensions 2–8192 per side and at most 32 million pixels (fixed input limits added during fixture-only baseline development). Decode single-frame RGB images (grayscale converted to RGB); reject alpha, unsupported modes, corrupt files, nontrivial EXIF orientation, and unsafe symlinks. Masks must be single-frame grayscale/1-bit binary (0/255), nonempty for anomalies, and match original image dimensions. Missing, orphan, corrupt, or incorrectly sized masks fail the manifest build. Good images have null masks.
- Resize the complete image directly to **256 × 256**, Pillow bilinear, no crop, no padding, no augmentation, no EXIF auto-rotation. This may distort aspect ratio; accepted in advance. RGB channel order; output contiguous float32 CHW in [0,1], dividing by 255. Masks: nearest-neighbor to 256 × 256, boolean HW. Never bilinear-interpolate labels. No data-derived normalization statistics.
- Pretrained branch only: fixed ImageNet mean `[0.485,0.456,0.406]`, std `[0.229,0.224,0.225]` applied to the same RGB tensor. The weight identifier and normalization are documented in [torchvision](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html); the no-crop 256×256 geometry is our explicitly fixed localization choice, rather than the weights’ classification center-crop recipe. Do not use this normalization for the simple baseline. Preserve original masks for later pixel metrics; future evaluation should map heatmaps back to original dimensions and explicitly document interpolation.
- Hash raw image and mask bytes with SHA-256; record paths relative to data_root, dimensions, category, official split, label, anomaly boolean, and assigned role. Reject identical image content appearing more than once (even within training) so duplicate samples cannot cross fit/calibration/test. This detects exact duplicates, not near-duplicate or semantic leakage. Inspection counts are metadata, never accuracy results.

## Normal-calibration threshold protocol

Target image-level false-positive rate **alpha = 0.05**. Higher scores mean more anomalous. Given n finite normal-calibration scores from an already fixed model, sort ascending and use the 1-based order statistic `k = ceil((n + 1) * (1 - alpha))`. Flag only `score > threshold` (strict comparison, conservative ties). If k > n, no finite distribution-free threshold is available: use +infinity, flag nothing, and explicitly report insufficient calibration data. The baseline implements this rule and stores calibration evidence; no real model scores exist yet.

Under exchangeable calibration and future normal images, and a scoring rule fixed independently of calibration, this split-conformal rank rule gives a **marginal** normal false-alarm probability no greater than alpha. It is not a guarantee of conditional/deployment FPR for this particular fitted threshold, and says nothing about defect recall. Reusing calibration to tune models invalidates the premise. Distribution shift, correlated images, and nonrepresentative acquisition can invalidate the guarantee.

Small samples yield coarse thresholds with resolution about `1/(n+1)` and high uncertainty in the normal tail. At 5%, at least 19 calibration images are needed for a finite threshold. For illustration only, n=42 gives k=41; this is arithmetic, not an observed dataset count or result. Record n, k, threshold, strict comparison, tie count, and target FPR with each future model. Never substitute test normals to increase n. Actual final-test FPR/recall must later be reported with denominators and uncertainty, without claiming a measured 5% FPR merely from this target.

## Final evaluation boundary

Before enabling final-test loading: freeze protocol, manifest digest, code version, model artifacts, and calibration thresholds. Only then evaluate official test images and original masks once for the prespecified comparison. Keep the raw dataset unchanged. Post-test error analysis may describe failures; any subsequent tuning must be labeled exploratory and cannot reuse the same test set as an untouched confirmatory evaluation.
