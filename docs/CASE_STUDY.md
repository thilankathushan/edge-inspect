# Edge Inspect: making anomaly detection inspectable

Visual inspection often has many normal examples and few representative defects. Edge Inspect explores a normal-only detector that explains a high image score spatially, while making calibration and runtime costs visible. The project targets one bottle category rather than claiming broad visual quality control.

I built a reproducible path from validated image/mask manifests to a classical RGB-template baseline, then a compact PatchCore-style detector. Normal training data is split before fitting; calibration sets thresholds but never populates the feature bank. Frozen configurations and pre-run artifact hashes preserve the distinction between a held-out evaluation and later exploration. Undefined metrics are reported explicitly.

The learned branch trades original PatchCore coreset complexity for a bounded, seeded 4096-patch reservoir and chunked exact nearest-neighbor search. It runs on CPU, saves provenance, and produces a coarse spatial map. The baseline remains useful as a transparent reference that exposes sensitivity to alignment and lighting.

The real bottle evaluation used 167 normal fitting images, 42 separate normal calibration images and 83 held-out test images. The learned model raised image AUROC from 0.8595 to 0.9460 and recall from 46/63 to 58/63 defects. This came with twice the false alarms: 2/20 normals rather than 1/20. Most of the gain was on contamination; the baseline caught all small breaks while the learned detector missed one. Frozen thresholds remained unchanged after evaluation.

Localization improved from 0.8375 to 0.9679 macro per-image pixel AUROC. That aggregation excludes normal-only masks and differs from pooled pixel AUROC. A visually useful map can still accompany a missed image: the representative small-break miss had excellent pixel ranking but stayed below the normal-calibrated threshold. Scores and attractive overlays are not interchangeable with reliable decisions.

Optimization produced an instructive negative result: on my Apple M2, the ONNX extractor path took about 311 ms median end-to-end on real calibration images versus 291 ms for the original runtime. It used less whole-process peak RSS, but nearest-neighbor scoring still dominated at roughly 256–259 ms. Exporting one component did not remove the main runtime cost. The original runtime remains the default; exact parity and test-runtime results are in REAL_ONNX_RESULTS.md.

The publisher download failed, so I documented a pinned third-party mirror, verified transfers and retained notices. I distinguish that evidence from independent publisher authentication. Data and model weights are excluded from the public repository; code, tests, aggregate results and permitted UI assets are published. The local Streamlit demo loads actual artifacts and validates uploads, while a generated sample makes the public walkthrough redistributable without claiming bottle quality from synthetic imagery.

The deliverable is a reproducible engineering prototype with a real frozen comparison, honest failure analysis, explicit export boundaries, local deployment and offline CI. Remaining limits are single-category/small-sample evidence, unverified publisher authenticity, weight redistribution rights and lack of production/camera/other-device validation. See the model card and release checklist; the [hosted demo](https://edge-inspect-demo.onrender.com) runs a labeled synthetic baseline and presents real evaluation results separately. Real bottle models are not uploaded.
